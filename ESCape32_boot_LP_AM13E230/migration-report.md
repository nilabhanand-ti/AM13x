### Area core

- `mcu/AM13E230X/config.c` — API replacements in `init()`: GPIO0 reset/power → `SYSCFG_DL_initPower()`; MCLKDIVCFG write → `DL_SYSCTL_setMCLKDivider(DL_SYSCTL_MCLK_DIV_2_DIV_4)`; FRI cache/wait-state sequence (incl. DSB/ISB and the 9-NOP "before returning to flash" wait) → `SYSCFG_DL_FLASH_init()`; added `SYSCFG_DL_Pinmux_init()` and `SYSCFG_DL_SYSCTL_init()`. The `__noinline__`/`.TI.ramfunc` attribute on `init()` was removed: its only purpose was the register-level FRI sequence, which the SDK now performs via its own RAMFUNC `DL_FRI_setReadWaitStates` (and the flash-crc step requires generated code not to be called from `.TI.ramfunc`). The register-level MCLK→SYSOSC switch is kept and runs **before** `SYSCFG_DL_FLASH_init` (0 wait states only after MCLK is 32 MHz, safe after a CPUSW reset from an app on HSCLK). CRC reset/power lines left untouched for flash-crc. `#ifdef IO_RXTX` block left for signal-io. Identifiers and comments preserved.
- `src/common.h` — header addition: `#include "ti_sdk_dl_config.h"` (after `<soc.h>`), so all units see the generated symbols and driverlib; identifiers preserved.
- `mcu/AM13E230X/config.h` — `CLK` → `MCLK_FREQ_HZ`, `IO_CLK` → `SEMIMCLK_FREQ_HZ` (generated macros, identical values 32 MHz / 16 MHz); selector logic and `#error`s untouched (signal-io); identifiers preserved.
- `src/main.c` — `done:` path additionally resets GPIO1–GPIO3 (`DL_GPIO_reset`), which generated `initPower` now powers (the reference only powered GPIO0, which stays powered as before). `RSTCAUSE` read remains the first statement, WEPROT/BOOTRST normalisation and the `SYSTEMCFG.FLASHECCRSTDIS` write (SysConfig emits none) remain before the record scan and `init()`. `DEVICEID`, magic/vector jump unchanged. UC4/CRCP resets are left to signal-io / flash-crc once they add those instances to `initPower`.
- `startup/startup_boot.c`, `linker/boot_ticlang.cmd`, `src/util.c` (BOOTRST) — no change needed. Verified libdriverlib `dl_fri.c.obj` places `DL_FRI_setReadWaitStates`/`DL_FRI_setZeroReadWaitStates` in an input section named exactly `.TI.ramfunc` (0x3C B), so the existing `.TI.ramfunc` load FLASH_BOOT / run RAM_C rule covers it; the used generated/driverlib code has no `.data`/`.bss`, so no `.cinit` is needed. Unreferenced `SYSCFG_DL_init` / `SYSCFG_DL_SYSCTL_CLK_init` / `DL_SYSCTL_configSYSPLL` should be dropped by section GC (build-verifier to confirm in the map).
- Syntax check (tiarmclang 5.1.1 `-fsyntax-only`, default and `IO_TIMER`+`IO_PIN_PA27`+`CRC_SELFTEST`) is clean for `config.c`, `main.c`, `io.c`, `util.c`.

### Area signal-io

- `mcu/AM13E230X/config.h` — selector logic: the default is now `IO_UC4` (when neither `IO_PA2` nor `IO_TIMER` is defined; previously `IO_PA2`). The `IO_TIMER`/`IO_PA2` `#error` and the `IO_RXTX` `#error` are kept. Two guards were added: `IO_UC4` is exclusive with the others, and the pin options are fixed (`IO_TIMER` needs `IO_PIN_PA27`; `IO_PA2` must not use it), because the SysConfig pins are fixed. Pin-table values are unchanged and were checked against the generated macros: `IOMUX_PINCM_PA26/PA27` = 26/27, UC0 RX/TX PF 8/9, TIMG4_0_CCP1 PF 3. Identifiers are preserved.
- `src/common.h` — added `IO_PIN` **15** for `IO_UC4`; codes 11–14 are kept. `TIM3_IDR` → `DL_GPIO_readPins(GPIO_SIG_TIMER_C1_PORT, GPIO_SIG_TIMER_C1_PIN)` (generated macros, same `DIN31_0` read). Identifiers are preserved.
- `src/io.c` — API replacements in `initio()`, plus a new `IO_UC4` path:
  - The reference RSTCTL/PWREN/NOP/IPMODE/CLKSEL/CLKDIV/IBRD/FBRD/LCRH/PINCM writes (`IO_PA2`) are replaced by `SYSCFG_DL_SIG_UART_PA26_init()`.
  - The TIMG4 RSTCTL/PWREN/NOP/CLKSEL/CLKDIV/CPS/CCLKCTL/PINCM/LOAD writes (`IO_TIMER`) are replaced by `SYSCFG_DL_SIG_TIMER_init()`. Power, reset and IPMODE come from the generated `initPower()` and pins from `Pinmux_init()`, both already called in `init()`.
  - The SysTick CTRL/LOAD/VAL writes are replaced by `SYSCFG_DL_SYSTICK_init()` + `DL_SYSTICK_enable()` (same 16 000 000-count / 500 ms period).
  - The new `IO_UC4` `initio()` branch and the `recvbuf()`/`sendbuf()` pair follow the source `IO_RXTX` two-wire semantics. They mirror the reference UC0 loop (single-read RXDATA error check, `VAL = 0` per byte, `COUNTFLAG` timeout, wait for BUSY clear) using DL_UART APIs on `SIG_UART_UC4_INST`.
  - The `IO_PA2` `recvbuf`/`sendbuf` (PF swap, N1a CTL0/TXE sequence) and the `IO_TIMER` compare/LACT/ZCOND/filter code are otherwise **unchanged**.
  - `recvval`/`sendval`/`recvdata`/`senddata` and all identifiers are preserved.
- `src/main.c` — `done:` additionally resets UC4 (`DL_UART_reset(SIG_UART_UC4_INST)`), which the generated `initPower` now powers in every build. TIMG4 and UC0 were already reset, and SysTick is still stopped. Identifiers are preserved.
- Issues and notes:
  - (a) The generated `SIG_TIMER` capture lands on CC1. `initio()` restores CC1 to compare mode right after the generated init. A cleaner fix is to re-model the capture on CC0 with the pair input in SysConfig.
  - (b) The reference IFCTL filter is FE + FP 3 on CC0, written at register level. The 8-TIMCLK STM32 filter value was not re-evaluated.
  - (c) The `IO_PA2` and `IO_UC4` paths enable UART majority voting, so that NERR keeps the source NF semantics. SysConfig does not set it.
  - (d) The pins PA0/PA1/PA26/PA27 keep their IOMUX functions across the jump to the app (peripheral resets do not clear PINCM).
  - (e) The default build now needs the LaunchPad XDS110 backchannel: J12 TX/RX shunts fitted, plus the jumper-wire workaround on Rev E1. Host tools must accept `IO_PIN` 15 and run two-wire with no echo.
- Verification:
  - tiarmclang 5.1.1 `-Oz -fsyntax-only` is clean for `io.c`, `main.c`, `util.c` and `config.c` in all three supported variants (default `IO_UC4`, `IO_PA2`, `IO_TIMER`+`IO_PIN_PA27`). The guard combinations fail as intended.
  - Object check of `io.c`/`main.c`: no `.data`/`.bss` (`UCx_INST_PTR` folds to a constant).
  - `io.c` `.text`: initio/recvbuf/sendbuf are 80/80/44 B for UC4, 44/76/92 B for PA2 and 80/164/124 B for TIMER.
